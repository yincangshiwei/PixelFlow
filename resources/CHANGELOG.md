# PixelFlow 版本日志

## 2026-09-03

### 高清放大 — 新增功能（DLSS 5 神经渲染）

- 图像处理新增「🔍 高清放大」功能，首期接入 NVIDIA DLSS 5 神经渲染 + DLSS 超分，支持单图与批量
- 放大引擎采用注册表驱动的动态参数面板：切换引擎即整体切换该引擎专属的参数组，各引擎参数在预设中按命名空间分别保存，互不覆盖
- DLSS 5 参数完整可调：放大档位（1× DLAA / 1.5× Quality / 1.724× Balanced / 2× Performance / 3× Ultra Performance）、NR 风格与强度、NR Preset、局部结构/局部色调/皮肤结构强度、DLSS 模型预设（Default/J/K/L/M）、Automatic Mask
- 新增「多趟放大」：目标倍数最高 8×，自动拆成多趟原生档位（如 4× = 2× 跑两趟），每趟送入 DLSS 的渲染尺寸都与输入 1:1，比单次 3× Ultra Performance 更保细节；趟次按倍率降序执行，触到输出上限时能保住更大的达成倍数
- 选中图片即实时显示预计输出尺寸、实际倍数与放大趟数；超出 7680×4320 上限时自动截断趟数并提示，不再等到处理失败才报错
- 显卡门禁：仅 RTX 40 系（Ada）及以上可用，RTX 30 系及以下、非 RTX 卡、非 Windows 系统一律阻断并给出具体原因；Windows 10、显存偏低、非官方支持的 40 系路径等以黄色提示呈现
- 透明图放大保留原图 Alpha 通道（DLSS 不处理透明），可选「透明区保护」把全透明区域 RGB 归零，避免输出 JPG/WEBP 时边缘出现脏色
- 放大前自动按 EXIF 方向转正、把带 ICC 配置文件的图片统一转到 sRGB，避免竖拍图横躺与广色域图输出后偏色
- 渲染后强制校验 DLSS 5 feature-18 真实执行的日志证据，未生效时直接报错，不会静默退化成普通缩放
- 同尺寸批量图复用一个渲染会话，避免每张图重建 D3D12/NGX；批处理结束或取消时自动关闭会话释放显存
- 配置中心新增「🔍 高清放大引擎」子页：硬件与系统检测、运行时目录管理、逐文件完整性校验、DLSSNR 版本识别、目录可写性检查、SHA256 比对、应急与调试开关、许可与免责说明
- 修正多显卡机器的架构误判：原先只取 nvidia-smi 第一张卡的计算能力，核显+独显或新旧卡混插时会把整机判成旧架构；现改为逐卡记录并按计算能力最高者判定，同时补充显存探测与老驱动的查询降级

### 高清放大 — 运行时一键安装

- 配置中心新增「一键安装 DLSS5 运行时」：从本项目 GitHub Releases 的固定地址下载 `DLSS5.Runtime.v5.0.zip`（约 147 MB，仅含图片放大所需的 5 个文件），解压到 `runtime/upscale/dlss5/`，安装完自动校验并展示结果；下载自动走「开发环境」配置的 GitHub 代理，失败逐级回退直连；支持取消，全程进度写入后台日志
- 下载地址由 `config.py` 统一管理（`DLSS5_BUNDLE_DOWNLOAD_URL` 固定直链优先，按 tag 的 API 查询兜底）；将来更新运行时包：同 tag 替换文件并同步文件名即可
- 安装器兼容两种包结构：精简布局（顶层即 `host/` + `dlss/`，当前 Releases 上传的即此）与完整便携包布局（含 `bin/runtime/{host,dlss}`，可带任意顶层目录前缀，ffmpeg 等无关内容不会被提取）

### 高清放大 — 运行时获取方式

- DLSS 5 依赖 NVIDIA 专有运行时（受 NVIDIA RTX SDK License 约束，禁止再分发）与 ReShade、RenoDX 组件，因此不随安装包和源码仓库分发；运行时包由维护者上传至本项目 Releases，配置页可一键下载提取，也可手动下载解压后指定目录
- 主程序与打包产物零新增依赖：渲染协议以标准库实现，像素处理沿用 Pillow，不需要为高清放大创建 Python 环境

## 2026-08-31

### 图片排版导出 — 统一比例排版

- 排版布局新增「统一比例排版」：不同比例的图片先归一化到同一比例再均匀排版，网格完全对齐、图片大小一致，全程等比缩放不变形
- 目标比例支持自动（取多数图片的比例）、1:1、4:3、3:4、16:9、9:16 及自定义宽高
- 补齐填充支持自动、纯色留白、模糊背景、透明填充；自动模式对透明底图片补透明底（相当于从原图补齐），不透明图片补所选纯色
- 读取图片尺寸时修正 EXIF 旋转方向，手机竖拍图不再判错比例
- 统一比例可与图片压缩叠加使用；透明填充遇 JPEG 压缩时自动回退 PNG 以保留透明通道
- 修复导出时预处理缓存流被提前关闭导致 "I/O operation on closed file" 报错的问题，PPTX/PDF/DOCX 导出均改为使用独立数据副本

### 抠图模型环境 — 修复强制重建失败

- 修复「强制重建环境」时旧环境目录因被杀毒软件或残留进程占用而删不干净，导致重建报"目录已存在"失败的问题
- 重建前自动关闭常驻抠图进程，删除旧环境改为带重试的稳健删除，创建命令可自动替换残留目录
- 环境目录确实无法删除时，提示会给出具体目录路径与手动删除指引

### AI 抠图 — 读图/推理/后处理流水线（阶段3性能优化）

- 推理仍串行使用常驻模型，预取与后处理队列深度受限，控制内存峰值
- 后台日志输出流水线启用状态，以及每批推理/后处理耗时
- 流水线异常时自动回退到原有串行 micro-batch 路径

### AI 抠图 — GPU 自适应 micro-batch（阶段2性能优化）

- 未开边缘精炼且使用 GPU 时，按显存自动选择 batch 1~3，多张图一次 tensor 推理
- 显存不足（OOM）时自动降半重试，并记住本会话上限，避免反复撑爆
- CPU 模式与「边缘精炼」仍逐张处理，保证稳定与边缘质量
- 后台日志：启动时输出模型/设备/micro-batch；每批显示 batch 序号与文件范围；完成行带 batch 与设备

### AI 抠图 — 预缩放推理 + 仅回传遮罩（阶段1性能优化）

- 未开边缘精炼时：大图先按 BEN2 同等方式缩至 1024×1024 再送模型，worker 只返回单通道遮罩，主进程放大后贴回原图像素
- 原图 RGB 不经 AI 管线重编码，网络输入与原先全尺寸路径等价，遮罩精度保持同级
- 开启边缘精炼时仍走全尺寸 RGBA，保证发丝/边缘色估计质量
- 大图批量时可明显降低临时文件体积与读写开销

### 透明图处理 — 画布布局按智能对象方式一次栅格化

- 主体以裁剪后的全分辨率作为源，布局只记录画布与占比参数，导出时再采样合成
- RGBA 预乘 Alpha 后重采样，减轻半透明边缘发灰、发虚
- 按缩小/放大幅度自动选择重采样算法，并提供标准/弱/关闭三档细节恢复（默认标准）
- 始终按主体占比缩放（含小图放大），保证批量标准化构图；已移除「低分辨率不放大」
